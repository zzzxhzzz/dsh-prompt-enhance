# 增强提示词（prompt-enhance）

这是 `dsh-prompt-enhance` 插件的人类/模型共用说明书。插件在 dsh 聊天输入区提供「增强提示词」按钮；当按钮不可用（插件未安装、被 profile 关闭、`enableButton: false`、页面未重载）时，按本技能手工完成同样的事。

## 什么时候该增强

- 需求是一句话口语：「帮我弄个排序」「这个报错修一下」——缺目标、缺输入、缺验收标准。
- 需求包含多个隐含步骤，但没写执行顺序或输出格式。
- 用户明确要求「润色 / 优化 / 改写我的提示词」。
- 需求要交给另一个模型或 Agent 执行，需要它自解释、可直接落地。

## 什么时候不该增强

- 用户只要一个直接答案（「1+1」「今天几号」）：增强只会把问题变长。
- 需求已经精确（含目标、约束、输出格式、验收标准）：只做必要的轻量整理，或直接不改变。
- 用户要求「原样发送」「别改我的字」：不要改写。
- 涉及真实密钥、私人数据：不要在改写中复制或展开这些内容。
- 用户在描述的是一段代码/错误堆栈本身：先按原样保留，不要「优化」代码。

## 改写规则（硬性）

1. **保持原意**：不新增用户没提出的目标、范围、技术选型。
2. **不臆造事实**：缺的信息要么省略，要么写成待确认项，不要编造版本号、路径、API 名。
3. **不擅自扩大范围**：用户要「修一个函数」，不要升级成「重构整个模块」。
4. **保持原语言**：中文进、中文出；英文进、英文出；不要顺手中英混排或翻译。
5. **不为变长而扩写**：已经清楚的句子不要换一种说法再说一遍。
6. **只输出最终提示词**：不要解释、分析、标题、前后对比、「优化后：」这类前缀。

## 需要补全时可以补的内容

按缺失程度选择，不必八项齐全：

| 项 | 补什么 |
|---|---|
| 任务目标 | 一句话说清「要得到什么结果」 |
| 背景和上下文 | 现有代码/数据/报错的已知情况 |
| 角色 | 需要专业视角时（如「以 SRE 视角」） |
| 执行步骤 | 多步骤任务的顺序，避免并列歧义 |
| 输出格式 | 代码块 / 表格 / JSON / 只给结论 |
| 篇幅和语气 | 简明、正式、面向新人等 |
| 限制条件 | 不许改动的文件、必须用的库、性能上限 |
| 验收标准 | 怎样算完成（测试通过、字段齐全、可复现步骤） |

## 输出

只输出改写后的提示词本体，可直接粘贴进输入框。不要附加说明，也不要替用户发送。

## 手工使用（按钮不可用时）

1. 把用户原文当作「原始需求」；
2. 按上面的规则在脑中完成改写（必要时补全上表缺项）；
3. 把改写结果给用户，明确说这是可编辑的版本，原文未被修改；
4. 若用户不满意，保留原文，只重写，不要叠加第二版解释。

插件侧与本文档的元提示一致；如果两者出现分歧，以插件 `lib/prompt.js` 的 `META_PROMPT` 为准，并反馈这份文档需要更新。
